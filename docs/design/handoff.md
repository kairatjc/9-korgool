# Как дизайн из Claude Design превращается в код

Проблема: в Claude Design макет выглядит отлично, а реализация по handoff — заметно хуже.
Обычно это происходит по трём причинам:

1. **Реинтерпретация.** Разработчик (человек или ИИ) смотрит на макет и пишет стили заново —
   на дефолтах библиотеки (shadcn, Tailwind-утилиты «на глаз»). Мелкие расхождения в отступах,
   шрифтах, тенях и цветах накапливаются, и «магия» пропадает.
2. **Невоспроизводимый макет.** Позиции подогнаны абсолютным позиционированием под один экран,
   доска нарисована вручную под одну позицию, значения разбросаны по CSS — перенести это в
   компоненты, работающие с любыми данными, нельзя без переделки.
3. **Нет проверки.** Никто не сравнивает результат с макетом объективно, поэтому
   «примерно похоже» считается готовым.

Решение — договор из двух частей:
[промпт](claude-design-prompt.md) заставляет Claude Design выдать **воспроизводимый код**
(токены, данные → разметка, фикстуры, детерминизм), а этот документ описывает, **как
реализация обязана этим кодом пользоваться** и как проверяется результат.

## 1. Handoff хранится в репозитории как есть

- Пакет из Claude Design кладётся в `design/handoff/` **без изменений** и коммитится отдельным
  коммитом. Это эталон. Любая новая итерация дизайна — новый коммит туда же, видно diff.
- Прототип можно открыть локально: `pnpm design:serve` (статический сервер на `design/handoff/`).

## 2. Перенос: копируем, а не перерисовываем

| Что в handoff | Куда в коде | Правило |
|---|---|---|
| `tokens.css` | `apps/web/src/styles/tokens.css` | копируется **байт в байт**; Tailwind-тема ссылается на эти переменные (`colors: { wood: 'var(--color-wood)' }`), а не на свои значения |
| `components.css` | `apps/web/src/styles/components/*.css` | разбивается по компонентам, **селекторы и значения не меняются**; классы `.k-*` остаются теми же |
| разметка в `index.html` | React-компоненты (`data-component` → имя компонента) | структура DOM та же: те же теги, порядок, классы; модификаторы → пропсы (`state="legal"` → `k-pit--legal`) |
| `board.js` (`renderBoard`, `ballPositions`, геометрия) | `apps/web/src/board/geometry.ts` | переносится как есть с типами; React рисует SVG из тех же чисел |
| `motion.js` | `apps/web/src/board/motion.ts` | те же длительности/easing из токенов; вход — `MoveEvent[]` из `@korgool/engine` (формат совпадает с промптом) |
| `copy.json` | `apps/web/src/i18n/{ru,ky,en}.json` | ключи те же |
| иконки Lucide | `lucide-react` | те же имена |
| шрифты | `<link>` в `index.html` | те же семейства и веса |

Запреты для реализации:
- не подменять стили дефолтами shadcn/ui: shadcn (Radix) используется только как **поведение**
  (фокус, модалки, доступность), внешний вид — классы из handoff;
- не «улучшать» и не округлять значения;
- Tailwind-утилиты — только для того, чего нет в handoff (служебная раскладка), и только через токены.

## 3. Проверка: попиксельное сравнение

Для каждого экрана из промпта (раздел 6.4) есть пара:

- **эталон**: `design/handoff/index.html?screen=X&fixture=Y&state=Z&static=1`
- **реализация**: dev-маршрут `/__design?screen=X&fixture=Y&state=Z&static=1` в `apps/web`
  (только в dev-сборке; рендерит тот же экран из той же фикстуры, через `parse()` движка).

Playwright-тест (`apps/web/e2e/visual.spec.ts`) снимает обе страницы в одинаковых условиях —
вьюпорты **360×780, 390×844, 1440×900**, шрифты загружены, анимации выключены — и сравнивает
через `pixelmatch`:

- порог: **≤ 0.5 %** отличающихся пикселей на экран (сглаживание шрифтов даёт шум);
- при превышении — тест падает и сохраняет `expected.png`, `actual.png`, `diff.png`
  в `apps/web/test-results/`;
- реализация считается готовой, только когда все пары зелёные.

Анимации проверяются отдельно: видео (Playwright `recordVideo`) прототипа и реализации
на одном и том же `MoveEvent[]`, просмотр бок о бок + сравнение таймингов из токенов.

## 4. Отклонения — только явно

Если что-то из handoff нельзя перенести один в один (например, ограничение браузера или
доступности), это записывается в `design/DEVIATIONS.md`: экран, что отличается, почему,
скриншот. Без записи отклонений быть не должно.

## 5. Как вы проверяете результат

- Страница `/__design/compare` (dev): эталон и реализация бок о бок для каждого экрана
  и вьюпорта, с переключателем «наложение/разница».
- В пул-реквестах с UI прикладываются `diff.png` для изменённых экранов.

## 6. Как передавать новую итерацию дизайна

1. В Claude Design попросить: «Обнови handoff по тем же требованиям (раздел 6 промпта)».
2. Положить пакет в `design/handoff/`, закоммитить.
3. Попросить Claude Code: «Синхронизируй реализацию с новым handoff». Он смотрит diff
   эталона, переносит изменения и доводит визуальные тесты до зелёного.
