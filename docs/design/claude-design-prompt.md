# Промпт для Claude Design

> Как пользоваться: скопируйте всё, что ниже линии, в Claude Design.
> Работайте в два шага (см. «Порядок работы» в самом промпте): сначала выбираете
> визуальное направление, потом Claude Design делает полный пакет передачи (handoff).
> Как этот пакет превращается в код — описано в [handoff.md](handoff.md).

---

Ты проектируешь UI веб-игры **«Тогуз коргоол»** — традиционной кыргызской настольной игры
семейства манкала. Это хобби-проект: браузерная игра, в которую играют с другом, со случайным
соперником или с ботом. Основная аудитория — Кыргызстан, много игроков с телефонов.

Главное требование к результату: **твой прототип будет перенесён в код один в один**.
Реализацию сделает Claude Code на React + Vite + Tailwind. Он не будет «вдохновляться»
твоим дизайном — он возьмёт твой HTML/CSS как исходник, перенесёт его в компоненты и
сравнит скриншоты реализации со скриншотами твоего прототипа попиксельно. Поэтому всё,
что ты делаешь, должно быть **воспроизводимым кодом**, а не картинкой. Правила для этого —
в разделе «Требования к handoff». Они важнее, чем любая визуальная идея: красивое, но
невоспроизводимое решение — плохое решение.

## 1. Игра — что нужно понимать дизайнеру

- Доска: **2 ряда по 9 лунок** (*отау*) — по ряду на игрока, плюс у каждого игрока
  **казан** — хранилище выигранных шариков.
- **162 шарика** (*коргоол*), в начале по 9 в каждой лунке. В одной лунке может оказаться
  от 0 до ~40 шариков (теоретически больше), в казане — до 162.
- Ход: игрок нажимает на **свою непустую лунку**, шарики раскладываются по одному в следующие
  лунки против часовой стрелки (по своему ряду слева направо, затем по ряду соперника).
- **Захват**: если последний шарик упал к сопернику и там стало чётное число — все шарики
  этой лунки улетают в казан игрока.
- **Туздук**: если последний шарик сделал в лунке соперника ровно 3 — лунка навсегда
  становится «туздуком» игрока (максимум один на игрока за партию). Всё, что в неё попадает,
  сразу уходит владельцу. Туздук нужно визуально выделить: традиционно отмечается «X»,
  нужен цвет/метка владельца.
- Победа — 82 шарика в казане. Ничья — 81:81.
- Игроки: **Белые** (ходят первыми) и **Чёрные** — это названия сторон, а не обязательно цвета
  шариков. Шарики у обоих одинаковые.
- Лунки нумеруются 1–9 **с точки зрения каждого игрока** (слева направо со своей стороны).
  Свой ряд всегда внизу (или, в вертикальной раскладке, ближе к игроку).

## 2. Визуальное направление

- **Одна тема**, без переключателя светлой/тёмной. Не делай тёмную версию.
- Национальный кыргызский стиль, но современный и чистый, не «сувенирный»: мотивы
  войлочного ширдака и орнамента (*кочкор мүйүз* и т.п.), тёплое дерево доски,
  шарики — гладкие камешки/косточки. Орнамент — сдержанно, как акцент, а не фон всего экрана.
- Доска — главный герой. Интерфейс вокруг неё — тихий.
- Шрифты — только из Google Fonts, обязательно с **кириллицей и кыргызскими буквами
  ң, ө, ү** (проверь на строке «Оюнчу, Бүркүт, Жеңиш, Өнөр»).
- Иконки — только из набора **Lucide** (укажи имена иконок, например `rotate-ccw`, `flag`).
  Свои рисованные SVG допустимы только для орнаментов и элементов доски.

## 3. Экраны (объём MVP)

Сделай все экраны в двух размерах: **телефон 390×844** и **десктоп 1440×900**.
Дополнительно проверь, что телефонная версия не ломается на ширине **360**.

1. **Главная.** Логотип/название, крупная кнопка «Играть» (случайный соперник), кнопки
   «С другом», «С ботом», «За одним устройством»; ссылки «Правила», «Обучение»; вход через
   Google в углу (или аватар, если вошёл); выбор языка (Кыргызча / Русский / English).
2. **Игра с ботом — настройка.** Уровень (4 уровня: Бала, Оюнчу, Чебер, Устат), цвет
   (белые / чёрные / случайно), контроль времени (3+2, 5+3, 10+5, 15+10, без часов — по умолчанию).
3. **Игра с другом — создание.** Контроль времени, цвет → экран ожидания: ссылка-приглашение,
   кнопки «Скопировать», WhatsApp, Telegram, 6-символьный код комнаты; «Ожидаем соперника…».
4. **Вход по коду комнаты.** Поле на 6 символов.
5. **Поиск соперника.** Одна очередь, контроль 5+3 фиксирован. Анимация поиска, таймер
   ожидания, кнопка «Отмена». Состояние через 30 с: предложение «Сыграть с ботом, пока ищем».
6. **Экран партии** — самый важный, см. раздел 4.
7. **Конец партии** (модальное окно поверх доски): победа / поражение / ничья, счёт казанов,
   причина (82 шарика, нет хода, время, сдача, соперник отключился), кнопки «Реванш»,
   «Новая игра», «На главную».
8. **Вход.** Только «Войти через Google» + «Продолжить как гость».
9. **Профиль.** Ник, аватар, страна/город; статистика (победы/поражения/ничьи, туздуков
   создано); история партий (список: соперник, результат, счёт, дата).
10. **Правила.** Текст с небольшими встроенными схемами доски (посев, захват, туздук).
11. **Обучение.** Один шаг интерактивного туториала: доска + подсказка «Нажмите на лунку 7»
    с подсвеченной лункой, прогресс «Шаг 2 из 6».
12. **Настройки.** Язык, звук вкл/выкл, вибрация, скорость анимации (медленно / обычно /
    быстро / без анимации), «переворачивать доску» в игре за одним устройством.

**Не делай** (сознательно вне проекта): чат, рейтинг, таблицу лидеров, друзей, турниры,
тёмную тему, вход по телефону/e-mail/Telegram.

## 4. Экран партии — подробно

Элементы:
- Доска: 18 лунок, 2 казана, счётчик-число в каждой лунке и в казане (число видно всегда).
- Плашки игроков (сверху соперник, снизу «я»): ник, аватар/инициалы, сторона (белые/чёрные),
  **часы** (обычное состояние; моё время идёт; осталось < 20 с — тревожное; время вышло),
  индикатор «ход соперника»/«ваш ход», значок «соперник не в сети».
- История ходов в нотации `1. 7x 3  2. 9X 5x` (x — захват, X — туздук); на телефоне —
  свёрнутая полоса/выезжающая панель, на десктопе — боковая колонка.
- Действия: «Сдаться», «Предложить ничью», «Перевернуть доску»; в игре с ботом также
  «Отменить ход» и «Подсказка». Сдача — с подтверждением.
- Оверлей «Переподключение…» и плашка «Соперник отключился, ждём 0:45».

**Раскладка доски.** На ширине 360–390 девять лунок в ряд не помещаются с удобной зоной
нажатия. Требование: **зона нажатия лунки ≥ 44×44 px**. Поэтому на телефоне в портретной
ориентации предложи **вертикальную доску** (два столбца по 9 лунок, казаны сверху/снизу или
по центру), на десктопе — горизонтальную. Обе раскладки должны быть строго описаны (см. 6.3).

**Состояния лунки** — нарисуй каждое:
`default` · `hover` (десктоп) · `pressed` · `legal` (можно ходить) · `disabled`
(чужая/пустая/не мой ход) · `last-move-from` (откуда был последний ход) ·
`last-move-to` (куда упал последний шарик) · `capture` (момент захвата) ·
`tuzdyk-mine` · `tuzdyk-opponent` · `hint` (подсказка/туториал) · `preview-target`
(при наведении на лунку подсвечивается, куда упадёт последний шарик, и метка «+10» /
«туздук» если будет захват/туздук).

**Отображение шариков.** Опиши правило для любого количества:
- 0 — пустая лунка;
- 1…N — шарики видны по отдельности, раскладка **детерминированная** (одинаковое число →
  одинаковая картинка, без случайности), задай координаты для каждого количества от 1 до N
  (N выбери сам, ориентир 12–16);
- больше N — «куча» + число.
Для казана — то же правило, своё N.

## 5. Анимация хода

Движок игры выдаёт список событий хода. Прототип должен **проигрывать именно такой список**
(вставь его в прототип как данные и сделай кнопку «Проиграть ход»):

```json
[
  { "type": "pickup",  "index": 8, "count": 9 },
  { "type": "sow",     "index": 8,  "toKazan": null },
  { "type": "sow",     "index": 9,  "toKazan": null },
  { "type": "sow",     "index": 10, "toKazan": null },
  { "type": "sow",     "index": 11, "toKazan": null },
  { "type": "sow",     "index": 12, "toKazan": null },
  { "type": "sow",     "index": 13, "toKazan": null },
  { "type": "sow",     "index": 14, "toKazan": null },
  { "type": "sow",     "index": 15, "toKazan": null },
  { "type": "sow",     "index": 16, "toKazan": null },
  { "type": "capture", "index": 16, "count": 10, "by": "white" }
]
```

Индексы доски: `0..8` — лунки Белых 1..9, `9..17` — лунки Чёрных 1..9; посев идёт по
возрастанию индекса по кругу. Другие события: `tuzdyk {index, by}` (лунка стала туздуком),
`sow` с `toKazan: "white"|"black"` (шарик попал в туздук и ушёл владельцу),
`collect {side, count}` (конец партии, игрок забирает свои шарики), `game_over {status}`.

Для каждого типа события задай: длительность, задержку между шариками, easing, траекторию
(дуга/прямая), что происходит со счётчиком. Все значения — токенами (см. 6.1). Предусмотри
скорости «медленно / обычно / быстро / без анимации» как множитель.

## 6. Требования к handoff (обязательные)

### 6.1. Токены — единственный источник значений
- Все цвета, шрифты, размеры шрифтов, межстрочные, отступы, радиусы, тени, z-index,
  длительности и easing — **CSS custom properties** в одном блоке `:root { … }`
  (`--color-…`, `--font-…`, `--space-…`, `--radius-…`, `--shadow-…`, `--duration-…`, `--ease-…`).
- В остальном CSS — **только ссылки на токены**, никаких «магических» `#a3542b` или `13px`
  в компонентах. Исключение — геометрия доски в SVG (она описана в 6.3).
- Продублируй токены как JSON (то же имя → значение).

### 6.2. Код прототипа
- Чистый **HTML + CSS + немного vanilla JS**, без фреймворков и без Tailwind.
- Раскладка — **flex/grid** и нормальный поток. Никакого `position: absolute` для подгонки
  элементов под конкретный экран (допустимо только для оверлеев, модалок, бейджей).
- Классы по схеме **`.k-<component>`, `.k-<component>__<part>`, `.k-<component>--<modifier>`**
  (например `.k-pit`, `.k-pit__count`, `.k-pit--legal`). Каждый компонент в разметке помечен
  `data-component="Pit"` (имя будущего React-компонента).
- Состояния — **только модификаторами классов** (`--legal`, `--tuzdyk-mine` …), а не
  отдельными копиями разметки.
- Доска рендерится **из данных** JS-функцией `renderBoard(state)`, где `state`:
  `{ pits: number[18], kazans: [w, b], tuzdyks: [indexOrNull, indexOrNull], turn: "white"|"black" }`.
  Никакой вручную нарисованной доски под конкретную позицию.
- Графика (доска, лунки, шарики, орнаменты) — **инлайн SVG**, сгенерированный кодом или
  вставленный как `<symbol>` + `<use>`. Без растровых картинок, без canvas, без картинок
  с текстом. Текстуры (дерево, войлок) — SVG-паттерны/градиенты/фильтры, описанные в коде.
- Шрифты подключаются `<link>` с Google Fonts — укажи точные семейства и веса.
- **Детерминизм:** никаких `Math.random()`, текущих дат и времени в отрисовке; одинаковые
  данные → одинаковые пиксели.

### 6.3. Спецификация доски (отдельный раздел/файл `board-spec`)
- `viewBox` доски для обеих раскладок (горизонтальной и вертикальной), координаты центров
  и размеры всех 18 лунок и 2 казанов, положение номеров лунок и счётчиков.
- Функция `ballPositions(count, slot)` → массив координат шариков для лунки/казана
  (то, по чему рисуется правило из раздела 4), размер и рисунок шарика.
- Как раскладка доски меняется между 360, 390, 768 и 1440 px (масштабирование viewBox
  или смена раскладки — с точными брейкпоинтами).

### 6.4. Навигация по прототипу и фикстуры
Прототип открывается по URL-параметрам, чтобы каждый экран можно было сфотографировать
автоматически:

`index.html?screen=<id>&fixture=<id>&state=<state>&static=1`

- `screen`: `home`, `bot-setup`, `friend-create`, `friend-wait`, `join-code`, `matchmaking`,
  `matchmaking-offer-bot`, `game`, `game-over`, `sign-in`, `profile`, `rules`, `tutorial`,
  `settings`.
- `static=1` — отключает все анимации и мигания (для скриншотов).
- `state` — для экрана `game`: `my-turn`, `opponent-turn`, `preview` (наведение на мою лунку 7),
  `low-time`, `reconnecting`, `opponent-offline`, `resign-confirm`.
- `fixture` — позиция на доске. Используй **ровно эти** позиции (формат:
  18 чисел лунок / казаны Б,Ч / туздуки Б,Ч (номер лунки соперника или `-`) / чей ход):

| fixture | позиция | что показывает |
|---|---|---|
| `start` | `9,9,9,9,9,9,9,9,9,9,9,9,9,9,9,9,9,9/0,0/-,-/w` | начало партии |
| `midgame` | `5,0,11,2,1,0,23,1,4,7,3,0,0,14,2,9,1,6/40,33/3,6/w` | куча из 23, пустые лунки, туздук у каждого |
| `endgame` | `0,0,1,0,2,0,0,3,0,1,0,0,0,0,0,2,0,0/78,75/4,7/w` | мало шариков, напряжённый счёт |
| `gameover` | `0,2,0,1,0,0,4,0,3,0,1,0,0,5,0,0,2,0/84,60/-,-/w` | победа белых 84:60 |

  Я играю за белых во всех фикстурах. Подсветка последнего хода в `midgame` — условная
  (для показа состояний): `last-move-from` — лунка соперника 5, `last-move-to` — моя лунка 3.
- Имена игроков в макетах: «Айбек» (я), «Бүркүт_42» (соперник), бот — «Устат (бот)».

### 6.5. Тексты
- Все строки интерфейса — в одном объекте `copy` с ключами (`home.play`, `game.resign` …) и
  значениями на **ru**, **ky**, **en**. В разметке — только ключи (`data-i18n="home.play"`),
  текст подставляет JS. Макеты показывай на русском; проверь, что кыргызские строки
  (обычно длиннее) не ломают раскладку.

### 6.6. Что сдать (структура handoff)
Если можешь — отдельными файлами; если нет — одним HTML с чётко разделёнными блоками
`<style id="tokens">`, `<style id="components">`, `<script id="copy" type="application/json">`,
`<script id="board">`, `<script id="motion">`:

```
handoff/
  README.md        — оглавление, шрифты, список экранов/состояний, известные компромиссы
  tokens.css       — :root с токенами
  tokens.json      — те же токены
  components.css   — стили всех компонентов (только через токены)
  index.html       — прототип со всеми экранами (навигация из 6.4)
  board.js         — renderBoard, ballPositions, геометрия
  motion.js        — проигрывание событий хода
  copy.json        — строки ru/ky/en
  components.md    — список компонентов: имя, назначение, части, модификаторы, состояния
  board-spec.md    — раздел 6.3 текстом
  assets/*.svg     — орнаменты и прочая графика, если вынесены
```

### 6.7. Самопроверка перед сдачей
- [ ] Ни одного захардкоженного цвета/размера вне `tokens.css` (кроме геометрии доски).
- [ ] Каждый экран открывается по URL из 6.4 и выглядит так же, как в макете.
- [ ] Все 4 фикстуры рисуются функцией `renderBoard`, не вручную.
- [ ] На 360 px нет горизонтальной прокрутки; лунки ≥ 44×44 px.
- [ ] Контраст текста ≥ 4.5:1, счётчиков на лунках ≥ 3:1.
- [ ] Нет `Math.random`, canvas, растровых картинок; иконки — Lucide по именам.
- [ ] Кыргызские буквы ң, ө, ү отображаются выбранным шрифтом.

## 7. Порядок работы

1. **Сначала** покажи **3 разных визуальных направления** только для экрана партии
   (фикстура `midgame`, телефон и десктоп) — палитра, шрифты, материал доски, шарики.
   Дождись моего выбора.
2. После выбора — сделай все экраны и состояния в выбранном направлении и собери handoff
   по разделу 6.
3. В конце перечисли в `README.md` всё, что ты упростил или не успел, — честно.
