# Технологии и стек

## Принципы выбора

1. **Один язык везде — TypeScript.** Правила игры пишутся один раз и используются
   на клиенте (подсветка ходов, бот), на сервере (проверка ходов) и в тестах.
2. **Сервер — источник истины.** Клиент только предлагает ход, сервер его проверяет.
   Так невозможно сжульничать, подменив состояние в браузере.
3. **Лёгкий клиент.** Аудитория — в том числе мобильные пользователи с медленным
   интернетом, поэтому SPA без тяжёлых фреймворков рендеринга и игровых движков.
4. **Простая эксплуатация.** Один сервер Node.js + PostgreSQL + Redis в Docker
   спокойно обслуживает тысячи одновременных партий; масштабирование — позже.

## Итоговый стек

| Слой | Технология | Почему |
|---|---|---|
| Язык | **TypeScript** (strict) | общие типы клиента и сервера, меньше ошибок |
| Монорепозиторий | **pnpm workspaces** + **Turborepo** | общий движок, кэш сборок |
| Игровой движок | собственный пакет **`@korgool/engine`**, чистый TS без зависимостей | детерминированный, легко тестировать |
| Фронтенд | **React 19** + **Vite** | быстрая разработка, огромная экосистема |
| Роутинг | **TanStack Router** | типобезопасные маршруты |
| Состояние | **Zustand** (игра) + **TanStack Query** (REST-данные) | минимум шаблонного кода |
| Стили | **Tailwind CSS** + **shadcn/ui** | быстрый адаптивный UI |
| Графика доски | **SVG** + **Motion** (Framer Motion) | чёткая доска на любом экране, анимация посева; Canvas/WebGL не нужен |
| i18n | **i18next** (ky / ru / en) | |
| PWA | **vite-plugin-pwa** (Workbox) | установка, офлайн для бота |
| Бот | движок в **Web Worker** (Comlink) | не блокирует UI, работает офлайн |
| Бэкенд | **Node.js 22** + **Fastify** | быстрый, с валидацией схем |
| Реальное время | **Socket.IO** (+ Redis adapter) | реконнекты, комнаты, fallback на long-polling для плохих сетей |
| Валидация | **Zod** | общие схемы сообщений клиента и сервера |
| БД | **PostgreSQL 16** | пользователи, партии |
| ORM | **Drizzle ORM** | типобезопасный SQL, лёгкие миграции |
| Кэш / очереди | **Redis** (Valkey) | общая очередь подбора (FIFO), состояние активных партий, часы (позже — онлайн-статусы) |
| Аутентификация | **Better Auth** (плагин `anonymous`) | гостевые сессии + Google OAuth; позже добавляется плагин `phoneNumber` без переделки схемы |
| SMS *(в планах)* | **Twilio Verify** или местный SMS-агрегатор КР | доставка OTP-кодов для входа по телефону; провайдер скрыт за интерфейсом `SmsSender` |
| Рейтинг *(в планах)* | **Glicko-2** (своя реализация или `glicko2` npm) | на старте подбор случайный, без рейтинга |
| Тесты | **Vitest** (юнит, движок), **Playwright** (e2e, две вкладки = два игрока) | |
| Качество кода | **ESLint**, **Prettier**, **TypeScript** в CI | |
| CI/CD | **GitHub Actions** | lint → test → build → deploy |
| Деплой | **Docker Compose** на VPS (Hetzner / локальный хостинг KG) + **Caddy** (HTTPS) | дёшево, просто; позже — Fly.io/K8s при росте |
| Мониторинг | **Sentry** (ошибки), **Prometheus + Grafana** или Uptime Kuma | |
| Аналитика | **Plausible** / **Umami** (self-hosted) | без cookie-баннеров |

## Требования к окружению разработчика

- Node.js 22 LTS, pnpm 9+
- Docker (для PostgreSQL и Redis локально)
- `pnpm dev` поднимает клиент и сервер, `docker compose up db redis` — инфраструктуру.
